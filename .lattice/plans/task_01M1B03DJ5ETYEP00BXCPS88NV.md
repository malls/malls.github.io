# Plan — FA-30: Shibuya canyon walls read as distinct buildings

Task: task_01M1B03DJ5ETYEP00BXCPS88NV · complexity: medium
Follow-up to FA-29 (bf5c7c0). User: "more realistic. lets make it look more like buildings."

## Problem

Each `.canyon-wall` is one continuous plane: a single asphalt fill, one wall-level
depth-fade + uniform floor/mullion `repeating-linear-gradient`s, one `.wall-windows`
overlay of specks and base spill, and `.wallstack` sign columns floating unanchored on
it. Real Shibuya walls are rows of distinct narrow buildings butted together: unequal
heights and stepped rooflines against the night, different facade tones, per-building
window rhythms, hard vertical seams, storefront bases, sign stacks bolted to a
*specific* building.

## Scope (files)

- `shibuya/index.html` — restructure wall markup (scenery region only; the `.street`
  near layer and everything readable is untouched).
- `shibuya/style.css` — replace wall/facade paint with per-building paint; responsive
  tweaks.
- `/index.html` (root) — regenerated by `node build.js`, committed with the sources.
- `shibuya/script.js` — **untouched** (it only touches `.pow`, all on the near layer).

## Approach

### 1. Buildings become the organizing unit inside the existing bands (§7)

Keep the proven skeleton — `.canyon` › `.canyon-road` + two `.canyon-wall`s (each
`.wall-band.band-mid.depth-mid` + `.wall-band.band-far.depth-far` › `.band-deep`) +
`.canyon-end`. The walls remain the two rotated planes under the one shared
perspective; everything below is flat paint on those planes, foreshortened by the
geometry (§7.1). **No preserve-3d, no translateZ, no new transforms besides the
existing band `scale()`s. No new `@keyframes`, no ids, no `:is()` — all plain classes
(build contract).**

Inside each band, wrap each `.wallstack` in a new `.bldg` div, so a band is a flex row
of buildings and each stack visibly belongs to one:

```
.wall-band.band-mid.depth-mid
  .bldg.bldg-a  > .wallstack (居酒屋 …)
  .bldg.bldg-b  > .wallstack (カラオケ …)
  .bldg.bldg-c.bldg-x > .wallstack (麻雀 …)
  .bldg.bldg-d.bldg-x > .wallstack (不動産 …)
.wall-band.band-far.depth-far
  .bldg.bldg-e > .wallstack (bulbs) [+ second bulb stack in one building]
  .bldg.bldg-f > .wallstack
  .bldg.bldg-g > .wallstack
  .band-deep  (unchanged — scale()-faked clutter beyond the buildings)
```

Depth architecture is preserved: the `.depth-mid` / `.depth-far` filters stay exactly
where they are, on the two bands (§7.2). **No per-building filters** — distance grading
within a band is done with paint (darker facade veils on farther models), never
`filter`, so we don't multiply rasterized layers. Sign spans, JA copy, and the bulb
species are all unchanged.

`aria-hidden="true"` stays on `.canyon` — everything here remains scenery (§7.3.1).

### 2. Building "models" — custom-prop bundles, ~1 div each

Define 7 model classes (`.bldg-a` … `.bldg-g`), each a small bundle of custom props;
one shared `.bldg` rule consumes them. Budget: ~14 new divs total (7 per wall), each a
single element with a multi-layer `background-image` — no per-window nodes.

```css
.bldg {
	position: relative;
	flex: 0 0 var(--bw);
	height: var(--bh);              /* bottoms align; rooflines step */
	box-sizing: border-box;
	display: flex;
	flex-direction: column;
	align-items: center;
	background-color: var(--facade);
	background-image: /* per-model layers, see below */;
}
.bldg > .wallstack { margin-top: var(--drop); }  /* replaces the nth-child staggers */
```

Per model, vary:

- **`--bh` height** (roofline): mid band ~72–96%, unequal, no two adjacent alike.
  Far band ≥85%, and the most-central (farthest) far building ~98% — see §7.1 note
  below.
- **`--bw` width**: unequal flex-basis %s (e.g. 30/23/27/20 across band-mid) — narrow
  Shibuya parcels, asymmetric (§6).
- **`--facade` tone**: grounds family only (§2). Base every facade on one of the three
  tokens (`--night`/`--asphalt`/`--board`) and split them into ~5 perceived tones with
  low-alpha veil gradient layers (`rgb(10 10 18 / …)` darkening or `--film-1`
  lightening) rather than inventing new hexes — palette compliance stays ironclad.
  Farther models within a band get darker veils (paint-based distance grading).
- **window rhythm**: per-model floor pitch (`repeating-linear-gradient(to bottom,
  --film-1 0 2px, transparent 2px <5.5–9vh>)`) and mullion pitch (`to right`, 2.5–6vw).
  Differentiate character: one dense office grid, one ribbon-window model
  (floors only, no mullions), one nearly blank board-tone infill, etc. All at
  `--film-1`-class alpha — structure, not glow (§2 films).
- **storefront base**: bottom-anchored layers — a `--film-2` fascia line at ~12–16%
  height and a low-alpha hue spill (`linear-gradient(to top, <hue/0.07–0.12>,
  transparent)`). Migrate the existing `.wall-windows` base-spill hues here
  (magenta/orange/yellow left, cyan/green/blue right) so the road-reflection story
  from FA-29 still lines up. Light glows, surface doesn't.
- **lit windows**: 2–3 models carry one or two tiny no-repeat warm speck layers
  (moved from `.wall-windows`); the rest are dark — someone's still up, not everyone.

Markup assigns models in a *different order* per wall (and different `--drop` stack
offsets), so the two walls don't mirror (§6 asymmetric-always).

### 3. Replace — don't stack — the wall-level paint

- `.canyon-wall`: **remove** `background-color` and all `background-image` layers
  (fade + uniform grids). The wall box becomes transparent; night air shows above the
  stepped rooflines. Drop `overflow: clip` from `.canyon-wall` so sign halos spill
  past seams (light crossing parcel lines is the realistic behavior); the 320px
  no-horizontal-scroll guarantee lives on `.canyon`'s clip (§7.3.6), which stays.
  Verify at 320px; if anything leaks, restore the wall clip (see Risks).
- Wall padding: `padding: 0` (plus tiny `gap` between bands). Buildings run to the
  plane's bottom edge — street level, behind the road's spill — and the roofline air
  now comes from `--bh`, not padding.
- **Delete `.wall-windows`** (both markup divs and both big CSS blocks). Its content
  is redistributed into building models (specks + base spill). Nothing uniform remains
  to show through the seams.
- `.wall-band`: `align-items: flex-end` (was flex-start) so buildings sit on the
  ground; `gap: 3px` — the **hard seam**: with the wall transparent, night reads
  through the gap as a true dark joint, foreshortened narrower toward the far end by
  the geometry for free. Remove the old `.band-mid/.band-far > .wallstack:nth-child`
  margin staggers (replaced by per-model `--drop`).
- **Right-wall ordering**: add `.canyon-wall-right .wall-band { flex-direction:
  row-reverse; }` so within-band child order is near→far on both walls and the
  darker-goes-farther veils read correctly. (The wall itself already row-reverses the
  bands.)

### 4. Rooflines and roof details

- **§7.1 check — addressed explicitly**: "the street ends in sign-haze, never in sky"
  governs the *terminus* (`.canyon-end` at the vanishing point), not the top of the
  frame. Night above a stepped roofline is exactly §1's canvas — standing in the
  canyon, looking up at night air. To keep the terminus itself walled: far-band models
  stay tall (≥85%, farthest ~98%), `.band-deep` clutter and the unchanged
  `.canyon-end` haze cover the convergence — ground and sky still never meet at the
  point.
- **Parapet**: `.bldg::before` — a 2px `--film-2` lit top edge, on most models. Pure
  film hardware, squarely §5.
- **One rooftop silhouette per wall, max**: one model's `::after` — a small
  `--asphalt` box (stair bulkhead / water tank) sitting above the roofline with a
  1px `--film-1` top edge. Rectilinear, unlit, cheap (§5); anything more (antenna
  forests, decay texture) drifts §9 cyberpunk — don't.

### 5. Responsive (§7.3.7, §6)

- `<700px`: `.band-far { display: none }` stays. Replace the `.wallstack-x` hide with
  `.bldg-x { display: none }` on the two buildings that carry those stacks — mid drops
  to 2 buildings per wall; delete the now-unused `.wallstack-x` rule (and drop the
  class from markup). Remaining buildings widen (`flex` allows growth at this
  breakpoint or bump `--bw`).
- 320px: `overflow: clip` on `.canyon` still guarantees no horizontal scroll; nothing
  new is positioned outside the walls. Verify with devtools at 320×568 both
  orientations.

### 6. Build + verify

1. Edit sources; preview standalone at `shibuya/index.html` (file:// and http).
2. `node build.js`; verify the combined root page at shibuya's mapped widths
   (check `sites.config.json` for the bucket) — id-free, class-only change should
   survive the prefixer trivially; confirm no `:is()`, no commas in functional
   pseudo-classes, no new at-rules beyond existing `@media`.
3. Commit `shibuya/*` + rebuilt `index.html` together. Branch-link if a branch is used.

## Acceptance criteria

- Each wall reads as 4 distinct mid buildings + 3 far buildings: stepped rooflines
  with night above, unequal widths, ≥4 visibly different facade tones (all grounds
  family §2), ≥3 distinct window rhythms per wall, hard night seams between
  neighbors, storefront base band on each, every sign stack contained by a building.
- No uniform wall-level grid or `.wall-windows` overlay remains; no grid continues
  across a seam.
- §7 geometry intact: two walls, one shared perspective, one central vanishing point;
  no preserve-3d/translateZ anywhere; depth filters still exactly two per wall (on
  the bands), none on `.canyon`, none per-building; scene static, `pointer-events:
  none`, `aria-hidden` unchanged.
- §10 checklist still passes end to end: all seven neons, one flicker ≥0.55 floor,
  no colour-on-colour type, readable layer flat/unfiltered/near and untouched (zero
  diffs inside `.street`), scene unchanged under reduced motion, no horizontal
  scroll at 320px (rotated walls included).
- Zero new `@keyframes`, zero ids, zero JS changes; `shibuya/script.js` byte-identical.
- Element budget: ~14 new divs total; every building is one div + ≤2 pseudo-elements;
  all paint static gradients.
- Standalone page and built root page both verified; `node build.js` run; sources +
  rebuilt root `index.html` committed together.

## Risks / notes for the implementer

- **Loss of the wall-level depth fade**: the old to-center darkening gradient dies
  with the wall background. Compensate with darker veils on farther models + the
  existing band filters. If the far end still reads too bright next to the haze,
  add a low-alpha night gradient as the *top* background layer of the far-band
  models only — do not reintroduce a wall-wide overlay above the stacks, and do not
  touch the band filters.
- **`overflow` on `.canyon-wall`**: dropping the wall clip lets glows breathe but the
  rotated plane overhangs — `.canyon` clip must absorb it; test 320px before
  committing. If anything leaks, restore `overflow: clip` on the wall and accept
  clipped halos at seams.
- **vh-pitched floor gradients** on % -height buildings: pitches are viewport-relative,
  so a 72% building shows fewer floors, not squashed ones — correct. Don't switch to
  %-pitches (they'd stretch per building height, wrong).
- **Right-wall `row-reverse` on bands** changes which markup stack lands where —
  re-check the §3.5 no-same-hue-adjacent rule across the *new* physical adjacencies
  (including across seams) after reordering.
- The `.band-deep` stacks stay direct band children (beyond-the-buildings clutter);
  if they visually float once rooflines step, tuck them behind the farthest building
  with a small negative margin rather than restructuring.
